# Bank_API

Невеликий навчальний REST-сервіс на Spring Boot, який імітує бекенд простого банківського застосунку.  
Проєкт показує базову авторизацію користувача і роботу з JWT-токенами (вхід, реєстрація, оновлення і вихід з системи).

## Технології

- Java 8
- Spring Boot 2.7 (spring-boot-starter-web)
- Maven
- JWT (бібліотека jjwt)
- JUnit 5 для юніт-тестів

## Запуск проєкту

1. Зібрати проєкт і підтягнути залежності:  
   mvn clean package

2. Запустити застосунок:  
   mvn spring-boot:run

За замовчуванням API доступне на адресі:  
http://localhost:8081

Порт можна змінити в файлі `application.yml`.

## Основні можливості

1) Реєстрація користувача  
   `POST /auth/register`  
   Вхідні дані: `username`, `password`, `email`, `birthday`, `phoneNumber`.  
   У разі успіху повертається статус і згенерований JWT-токен.

2) Авторизація (логін)  
   `POST /auth/login`  
   Вхідні дані: `username`, `password`.  
   Якщо логін і пароль вірні, повертається новий JWT-токен.

3) Оновлення токена  
   `POST /auth/refresh`  
   Запит має містити токен у заголовку  
   `Authorization: Bearer <token>`  
   Повертається новий токен, а старий додається в чорний список.

4) Інвалідація токена (logout)  
   `POST /auth/invalidate`  
   Також очікує токен у заголовку.  
   Після виклику токен потрапляє в чорний список і більше не вважається валідним.

## Робота з токенами

Параметри токенів задаються в `application.yml` (назва застосунку, секретний ключ, час життя в секундах).  
Сервіс `TokenServiceImpl` генерує JWT з такими основними полями:

- логін користувача (subject);
- назва застосунку (issuer);
- email;
- час створення;
- час закінчення дії.

Для захищених ендпойнтів використовується власна анотація `@RequireToken` та інтерцептор `TokenAuthInterceptor`.  
Інтерцептор зчитує токен із заголовка, перевіряє його через `TokenService`, а при успішній перевірці підкладає метадані користувача в `HttpServletRequest`, щоб їх можна було використати далі в контролерах.

## Тести

Для сервісу токенів створено юніт-тест `TokenServiceImplTest`.  
Тест перевіряє, що:

- згенерований токен містить правильні дані (логін, email, назва застосунку, дати);
- щойно створений токен є валідним;
- після інвалідації токена через сервіс він більше не проходить перевірку.
